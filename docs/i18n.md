# Bilingual UI (zh/en)

TikLocal ships a single UI that switches between Simplified Chinese and English
per device. The implementation is deliberately dependency-free: a Python dict of
translations, a Jinja helper, and one small client script. No Flask-Babel, no
gettext, no build step.

## Locale resolution

`tiklocal/i18n.py` resolves the locale in this order:

1. `lang` cookie — written when the user picks a language on the settings page
   (per device, so a phone and a desktop can differ).
2. `Accept-Language` header — the highest-quality tag that explicitly names a
   supported locale; an unsupported language such as `ja` or `fr` falls through
   to the default instead of half-matching.
3. `zh` — the default.

`current_locale()` returns the locale of the active request (or the default
outside one), `translate(locale, key, **params)` formats a key, and `t(key,
**params)` is the request-aware shorthand for Python code.

The settings page stores the choice in the cookie **and** in
`localStorage['tiklocal:lang']` and then reloads, so server-rendered markup and
client scripts always agree.

## Where the strings live

| Location | Purpose |
| --- | --- |
| `tiklocal/i18n.py` | `TRANSLATIONS` dict (`zh` + `en`) for shared chrome, navigation, page titles and the settings page |
| `tiklocal/i18n_pages_flow.py` | `flow.*` keys: the Flow feed, Douyin mode, collection picker |
| `tiklocal/i18n_pages_library.py` | `library.*`, `home.*`, `saved.*` keys: library, timeline, home, favorites, collections |
| `tiklocal/i18n_pages_media.py` | `detail.*`, `image.*`, `download.*`, `login.*` keys: detail pages, image viewer, download, login, shared client scripts |
| `tiklocal/i18n_pages_radio.py` | `radio.*` keys: the radio page and its scene/ambience controllers |
| `tiklocal/i18n_pages_search.py` | `search.*` keys: the Douyin-style search page, its result cards and the feed's search button |

Each `i18n_pages_*.py` module exports `TRANSLATIONS = {'zh': {...}, 'en':
{...}}` and is merged into the main table at import time by
`_merge_page_catalogs()`. The split exists so two page conversions can proceed
in parallel without editing the same file; a duplicate key raises `ValueError`
instead of silently shadowing the original.

Both locales must define exactly the same key set, and `zh` is the source of
truth for tone: `tests/test_i18n.py` enforces the parity.

## Using a key

Templates get `t` from a context processor:

```jinja
<h1>{{ t('saved.title') }}</h1>
<span>{{ t('library.organize.selected', n=count) }}</span>
```

Catalog entries use `str.format` placeholders:

```python
'library.organize.selected': '已选 {n} 项',
```

Client scripts read the table that `base.html` inlines as
`window.__TIKLOCAL_I18N__` and use the helper exposed by
`tiklocal/static/i18n.js`:

```javascript
const T = (key, params) => window.TikLocalI18n?.t(key, params) ?? key;

showToast(T('flow.caption.copied'));
setLabel(T('library.organize.selected', { n: count }));
```

The `?? key` fallback keeps a page usable if the catalog fails to load: the raw
key is ugly but visible, which is easier to spot than an empty label.

`js_catalog(locale)` returns the whole table for the locale, so every key is
available to scripts on every page. The payload is a few tens of kilobytes of
JSON inlined into the HTML — acceptable for a LAN app, and it keeps the client
free of a second request and of per-page key lists.

## Rules for new strings

- Never hardcode user-facing copy in a template or controller; add a key.
- Put the key in the catalog module that owns the page, not in `i18n.py`.
- Prefix with the page domain (`flow.`, `library.`, `radio.`, …) and group with a
  second segment (`flow.caption.expand`, `radio.scene.paused`).
- Reuse the existing `common.*` keys (`cancel`, `confirm`, `close`, `delete`,
  `save`, `loading`, `retry`, `all`, `open_settings`) instead of adding
  near-duplicates.
- Do not translate identifiers, CSS classes, URLs, API field names, log lines,
  filenames or user data.
- Translate the accessibility copy too: `title`, `aria-label`, `placeholder`,
  `alt`.

## Date and number formatting

The `timestamp_to_date` filter formats dates per locale (`2024-06-01 09:00:00`
in Chinese, `Jun 1, 2024 09:00:00` in English), and client scripts pick
`zh-CN`/`en` for `Intl`/`toLocaleString` from `document.documentElement.lang`.

## Verifying a change

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_i18n.py -q   # parity + merge guards
node --check tiklocal/static/<controller>.js                 # syntax
```

Render a page in both locales without a browser:

```python
from tiklocal.app import create_app
app = create_app({'TESTING': True, 'MEDIA_ROOT': tmp_path})
client = app.test_client()
client.get('/library', headers={'Cookie': 'lang=en'}).get_data(as_text=True)
```

Finally load the page in a browser, switch the language on the settings page,
and confirm the page chrome, empty states, dialogs and toasts all follow the
switch without a stale string in either direction.
